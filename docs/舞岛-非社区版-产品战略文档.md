# 舞岛（非社区版）· 产品战略文档

版本：v1.1
日期：2026-08-24
撰写：产品通
状态：待评审（v1.3 对齐代发撮合方案）

> 本文档整合非社区版舞岛的产品战略层——用户、获客、价值、模块、内容建设。功能规格详见《舞岛MMVP-PRD-非社区版》。

---

## 一、产品定位

**舞岛是街舞人的内容资讯 + 官方活动平台 + 代发练舞撮合。**

用专业 PGC 内容吸引街舞人，用活动聚合留住回访，用**代发撮合**（用户提需求 → 平台审核发布练舞局 → 应征制联系）在个人主体无 UGC 资质下，间接验证「找搭子」是否真实高频。不依赖用户公开发帖，不依赖支付交易。

**一句话**：让街舞人在这里看到懂行的内容，找到值得参加的活动，**也能找到练舞搭子（平台代发）**。

## 二、用户是谁

### 2.1 战略层：三类核心用户

| 用户类型 | 特征 | 核心诉求 | 在产品里的角色 |
|---|---|---|---|
| **新手舞者** | 20-25 岁，学舞 <1 年，街舞圈新人 | 学舞、找灵感、了解街舞圈、**找同城练舞搭子** | 内容消费者 + **搭子需求提交者/应征者**（核心拉新） |
| **进阶/资深舞者** | 练舞 1-5 年，常参赛，有圈内人脉 | 专业信息、赛事、Workshop、**组队练舞/拼团大师课** | 内容消费者 + **搭子发起人**（核心留存） |
| **泛围观爱好者** | 不一定亲自跳，但喜欢街舞文化 | 刷有审美的街舞内容，了解文化 | 内容消费者（流量补充） |

### 2.2 供给侧：内容与合作来源

| 供给方 | 角色 | v1 合作方式 |
|---|---|---|
| **舞蹈老师/舞者 KOL** | PGC 内容作者 | 受邀供稿（穿搭/康复/训练方法/新鲜事） |
| **赛事方** | 活动信息来源 | 活动收录 + 推广位（v1 免费，建立关系） |
| **舞室/工作室** | 活动信息来源 | 活动收录（大师课/Workshop/Jam） |
| **平台编辑团队** | PGC 内容编辑 + **搭子需求审核代发** | 文化/赛事报道；审核用户需求并发布练舞局 |

### 2.3 不服务的用户（v1 Non-goals）

- **街舞从业者（品牌方/赞助商）**：v1 无商业广告位，不服务
- **想用户自发发帖/公开评论的用户**：无 UGC 资质，v1 不做；搭子通过**代发撮合**间接服务

## 三、用户从哪来

### 3.1 冷启动期获客策略

| 渠道 | 方式 | 预期成本 | 转化路径 |
|---|---|---|---|
| **微信生态内** | 公众号/视频号导流到小程序 | 低（自有渠道） | 文章/视频挂小程序卡片 |
| **小红书** | 街舞垂类内容种草，简介挂小程序 | 中（内容生产成本） | 内容→主页→小程序 |
| **抖音** | 街舞短视频，评论区引导 | 中（算法不确定） | 视频→主页链接→小程序 |
| **赛事合作** | 赛事方公众号/海报挂"舞岛赛事页" | 低（互利合作） | 线下/线上赛事曝光 |
| **舞室合作** | 舞室公众号/朋友圈推广"舞岛活动收录" | 低（互利合作） | 舞室学员转化 |
| **KOL 合作** | 舞者 KOL 供稿 + 个人推广 | 中（分成/稿费） | KOL 粉丝转化 |

### 3.2 冷启动期单城市策略

**选北京**：街舞氛围浓、舞室密度高、赛事频繁、KOL 集中、用户在本地有线下触点。

**单城市做透的好处**：
- 活动信息密度足够（每周 5+ 场活动可收录）
- 内容有本地视角（"北京本周街舞动态"）
- 线下活动曝光效率高（海报/舞室/赛事现场都能推广）
- 用户口碑裂变效率高（同城熟人圈）

**复制节奏**：北京跑通 3 个月后，复制到上海、广州、成都。

### 3.3 不做的获客方式

- ❌ 买量投放（v1 无商业化，ROI 算不过来）
- ❌ 现金补贴拉新（街舞圈是关系型圈子，补贴吸引的是羊毛党）
- ❌ 泛品类内容引流（不匹配定位，流失率高）

## 四、用户为什么来

### 4.1 用户在别处得不到什么

| 场景 | 现有替代方案 | 痛点 | 舞岛的价值 |
|---|---|---|---|
| **看街舞专业内容** | 抖音/小红书/B站 | 娱乐化、碎片化、缺乏深度沉淀型内容（穿搭/康复/文化） | 专业垂类内容阵地，懂行人做内容，信息密度高 |
| **找近期赛事** | 微信群刷屏、公众号分散、赛事官网更新慢 | 信息碎片化，错过报名/观赛 | 赛事聚合 + 分类筛选 + 关注提醒，一站看全 |
| **找大师课/Workshop** | 舞室公众号、朋友圈转发 | 信息被动接收，容易漏 | 活动平台主动发现 + 地图模式找附近 |
| **找附近 Jam/Cypher** | 熟人介绍、微信群 | 新人无法融入 | 活动地图模式，按距离发现 |
| **找练舞搭子** | 微信群/小红书/碰运气 | 信息散、新人难发、隐私顾虑 | **代发练舞局 + 应征制**，平台审核后代发 |

### 4.2 核心价值主张（按用户类型）

| 用户类型 | 价值主张 |
|---|---|
| 新手舞者 | "看懂街舞，找到活动和练舞搭子" |
| 进阶/资深舞者 | "专业内容 + 赛事 + **代发组队**，一站搞定" |
| 泛围观爱好者 | "刷有审美的街舞文化内容，了解这个圈子" |

### 4.3 信任感的建立

街舞圈对"懂行"极敏感。舞岛建立信任感的方式：

1. **PGC 内容的专业度**——穿搭/康复/训练方法由圈内 KOL/老师撰稿，不是编辑瞎写
2. **活动信息的完整性**——赛事详情含日程/舞种/级别/报名链接，不是干巴巴的标题+海报
3. **不装"什么都懂"**——v1 聚焦街舞垂类，不做泛舞蹈/泛健身，保持聚焦
4. **视觉调性**——紫色主色 + 编辑型长内容格式，传递"专业媒体"而非"工具小程序"的感觉

## 五、产品核心价值

### 5.1 价值三角

```
        专业 PGC 内容
         （拉新 + 种草）
              │
              │
   ───────────────────────
   │                     │
   │                     │
官方活动平台          代发练舞撮合
（留存 + 回访）      （差异化 + 搭子验证）
              │
           信任感
        （垂类专业认知）
```

**四个角的分工**：
- **专业 PGC 内容**：拉新入口
- **官方活动平台**：留存引擎（赛事/Jam/大师课 + 提醒）
- **代发练舞撮合**：差异化核心——在无 UGC 资质下验证找搭子需求；用户提私密需求，平台 PGC 发布，应征制撮合
- **信任感**：懂行内容 + 审核代发（比野生群更可控）

### 5.2 与竞品的差异

| 维度 | 抖音/小红书 | 公众号 | 微信群 | **舞岛** |
|---|---|---|---|---|
| 内容深度 | 碎片化 | 有深度但分散 | 无沉淀 | **编辑型长内容，结构化沉淀** |
| 街舞聚焦 | 泛娱乐 | 单个账号视角 | 信息碎片 | **街舞垂类一站看全** |
| 活动信息 | 无 | 单篇推文 | 刷屏易漏 | **聚合 + 筛选 + 地图 + 提醒** |
| 关注提醒 | 无 | 需手动看 | 通知噪音大 | **订阅消息，赛前 3 天/1 天精准推送** |
| 找练舞搭子 | 群聊/小红书 | 无 | 信息散、难沉淀 | **代发练舞局 + 应征（联系方式私密）** |
| 专业信任 | 流量驱动 | 单点信任 | 圈子信任 | **垂类阵地 + 编辑型内容 + 审核代发** |

### 5.3 护城河判断

**v1 的护城河很浅**——PGC 内容谁都能做，活动信息公众号也能发。真正的壁垒要靠：

1. **内容积累**：3-6 个月积累 100+ 篇深度内容，形成"街舞内容库"的认知
2. **活动关系网**：和赛事方/舞室/KOL 建立稳定合作，活动信息首发权
3. **用户习惯**：让街舞人形成"看活动找舞岛"的习惯，比内容本身更难被替代
4. **后续升级**：代发数据验证成立后，注册**有限公司 + ICP 备案**，补齐真 UGC 搭子 + 评论 + 交易

## 六、主要功能模块

### 6.1 模块全景

```
舞岛（非社区版 v1.3）
├── Tab1 首页
│   ├── PGC 内容流（6 类）+ 分类 tab + 搜索
│   └── 内容详情页
│
├── Tab2 活动
│   ├── banner：找练舞搭子 · 提交需求，审核后代发
│   ├── 活动列表（练舞局/官方/赛事/大师课/Jam）+ 地图
│   ├── 活动详情（练舞局→应征；其他→关注）
│   └── 提交搭子需求 / 提交成功
│
└── Tab3 我的
    ├── 浏览历史 / 关注的活动
    ├── 我的搭子需求 + 应征列表
    └── 设置（通知/搭子代发须知）
```

### 6.2 模块职责

| 模块 | 核心职责 | 关键指标 |
|---|---|---|
| **首页内容流** | 拉新入口，用专业内容吸引街舞人首次访问和持续浏览 | UV、人均浏览篇数、长文阅读完成率 |
| **内容详情页** | 沉淀型阅读体验，建立"专业媒体"信任感 | 阅读完成率、分享率 |
| **活动列表** | 留存引擎，让用户发现值得参加的活动 | 活动详情页访问率、关注转化率 |
| **活动地图** | 按距离发现附近活动，降低发现门槛 | 地图模式使用率、pin 点击率 |
| **活动详情页** | 完整活动信息 + 关注/应征 | 关注转化率；练舞局应征率 |
| **代发撮合** | 私密提需求 → 审核发布 → 应征撮合 | 需求提交量、成局率、发起复购 |
| **我的搭子需求** | 发起人查看应征、标记结束 | 应征查看率、成局确认率 |
| **关注的活动** | 个人回访入口，让用户有理由回来 | 关注列表回访率、取消关注率 |
| **浏览历史** | 跨设备同步已读内容，提升留存 | 浏览历史回访率 |
| **搜索** | 主动找内容/活动的入口 | 搜索 PV、搜索结果点击率 |

### 6.3 不做的模块（Non-goals）

| 不做 | 原因 |
|---|---|
| UGC 用户自发发帖 | 个人主体无社交类目 |
| 用户公开发评论/点赞 | 互动需社交类目 |
| 打卡挑战 | 防作弊无解、激励不足（v1.3 移除） |
| 拼团/商城/支付 | 无支付资质 |
| 用户主页/关注人 | 属于社交功能 |
| 站内 IM / 公开互动消息流 | v1 仅订阅消息 + 应征列表，无双向 IM |
| 节拍器/赛事日历/舞室地图工具 | v1 聚焦内容+活动，工具不优先 |
| 推荐算法 | v1 内容量小，时间倒序即可 |
| 直播/录播上课 | 需对应资质，开发成本高 |

## 七、内容和信息来源建设

### 7.1 PGC 内容体系（6 大类）

| 内容分类 | 内容方向 | 生产方 | 频率目标 | 来源建设方式 |
|---|---|---|---|---|
| **穿搭** | 舞种穿搭指南、装备选品、OOTD | 舞者 KOL / 时尚编辑 | 每周 1-2 篇 | ① 邀请圈内会穿搭的 bboy/bgirl 供稿；② 平台编辑整理+约稿；③ 合作舞室/品牌提供素材 |
| **康复** | 训练损伤预防、康复方法、热身拉伸 | 康复师 / 体育医学专业人士 | 每周 1 篇 | ① 找有街舞伤损经验的康复师约稿；② 整理公开医学资料+舞者访谈；③ 和康复机构合作 |
| **文化** | 舞种起源、文化事件、人物故事、书影音推荐 | 平台编辑 / 街舞文化研究者 | 每周 1 篇 | ① 编辑团队深度撰写（参考书籍/纪录片）；② 邀请街舞文化研究者供稿；③ 翻译整理海外资料 |
| **赛事** | 赛事预告、赛果报道、赛事分析 | 平台编辑 / 赛事方合作 | 每周 2-3 篇 | ① 赛事方官方信息+编辑整理；② 现场观赛报道；③ 选手访谈 |
| **新鲜事** | 大师课/Workshop 信息、老师介绍、课程内容 | 其他 / 平台编辑 | 每周 1-2 篇 | ① 其他主动提供课程信息；② 平台编辑整理发布；③ 和新鲜事联动活动平台 |
| **其他** | 舞室评价、老师专访、教学理念 | 平台编辑 | 每两周 1 篇 | ① 编辑走访舞室+采访；② 其他自荐；③ 学员口碑整理（PGC 编辑，非 UGC） |

**冷启动内容储备**：上线前 ≥40 篇（6 类 × 每类 ≥6 篇），保证首日内容厚度。

### 7.2 活动信息来源

| 活动类型 | 来源 | 采集方式 | 更新频率 |
|---|---|---|---|
| **赛事** | 赛事方官方、街舞媒体、舞室转发 | ① 赛事方主动提交；② 编辑主动收录；③ 微信群/公众号监测 | 每周新增 2-5 场 |
| **大师课/Workshop** | 其他 | ① 舞室主动提交；② 编辑合作约课信息 | 每周新增 3-8 场 |
| **Jam / Cypher Night** | 舞室/舞者社群 | ① 舞室主动提交；② 编辑监测同城活动 | 每周新增 1-3 场 |

**活动信息采集流程**：
1. 发现活动（赛事方提交 / 编辑监测 / 舞室合作）
2. 编辑核实（时间/地点/舞种/级别/报名链接）
3. 录入活动平台（PGC 后台）
4. 上线展示（列表 + 地图）
5. 持续更新（赛前提醒、赛果回填）

### 7.3 内容合作方建设

| 合作方类型 | 合作模式 | v1 目标数量 | 合作权益 |
|---|---|---|---|
| **舞者 KOL** | 稿费约稿 / 互换曝光 | 5-10 人 | 个人 IP 曝光、活动信息首发权 |
| **赛事方** | 免费收录 + 推广位 | 3-5 家 | 赛事曝光、报名引流、赛前提醒推送 |
| **舞室/工作室** | 免费收录活动 | 10-20 家 | 活动曝光、学员引流、舞室介绍内容 |
| **康复师/医学专家** | 稿费约稿 | 2-3 人 | 专业 IP 曝光、机构导流 |
| **街舞文化研究者** | 稿费约稿 / 联合策划 | 1-2 人 | 个人 IP 曝光、内容署名 |

### 7.4 内容生产流程

```
选题策划（编辑 + 数据反馈）
    ↓
约稿/撰写（KOL / 编辑 / 合作方）
    ↓
内容审核（专业度 + 事实核查 + 合规）
    ↓
编辑排版（Markdown 编辑器：H3/引用块/图片）
    ↓
发布上线（首页信息流 + 分类标签）
    ↓
数据监控（阅读完成率、分享率、UV 贡献）
    ↓
迭代选题（高完成率的方向多约稿）
```

### 7.5 内容质量底线

- **专业度**：每篇内容由圈内人/专业人士把关，不接受编辑瞎写
- **事实核查**：赛事信息/文化事实需二次核实（不靠 AI 编造）
- **合规**：不涉及敏感话题、不搬运侵权内容、PGC 内容也配置安全审核
- **署名**：KOL/专家供稿必须署名 + 简介，建立个人 IP 信任感
- **深度**：单篇 ≥800 字，编辑型长内容 ≥1500 字，不做"标题党"短文

## 八、产品演进路线

### 8.1 v1.3（当前·非社区版 + 代发撮合）

**目标**：验证「专业内容 + 活动信息 + **代发找搭子**」在街舞垂类的价值

**范围**：PGC 内容流 + 活动平台 + **代发练舞撮合（方案 B）**

**成功指标**：
- 次周留存 ≥20%；人均浏览 ≥3 篇
- 活动关注转化率 ≥15%
- **4 周需求提交 ≥30 条；成局率 ≥25%**
- 审核代发中位时效 ≤24h
- 周均新增 PGC ≥5 篇

### 8.2 v1.4（上线后 4–6 周）

- 代发运营 SOP 固化（审核 checklist、成局回访）
- 活动地图按时间筛选
- 数据看板加入撮合漏斗
- 微信群作备用撮合通道（活动详情页入口）

### 8.3 v2（公司 + ICP 备案后）

**前置条件**：注册**有限公司**（非个体工商户）+ ICP 备案 + 社交类目 + 内容安全 API

**新增能力**：
- 用户自发搭子帖（去掉代发中间层）
- 评论/点赞/收藏、消息中心
- 支付 → 拼团/商城

**产品形态跃迁**：代发撮合 → 真 UGC 社区（回到原 MMVP PRD 完整形态）

### 8.4 关键决策点

| 决策点 | 触发条件 | 决策内容 |
|---|---|---|
| 是否注册公司 | 内容留存 + **代发成局率**达标 | 注册有限公司 + ICP 备案 |
| 是否补齐真 UGC 搭子 | 公司主体 + 社交类目通过 | 用户自发发帖，下线代发流程 |
| 是否补齐交易 | 企业主体 + 微信支付商户号 | 拼团/商城/推广位上线 |
| 是否做多城市 | 北京单城市 DAU ≥1000 | 复制到上海/广州/成都 |

## 九、风险与开放问题

### 9.1 关键风险

| 风险 | 影响 | 应对 |
|---|---|---|
| **个人主体资质不确定** | 资讯/工具类目是否通过审核 | 上线前确认类目，必要时调整功能 |
| **内容生产能力不足** | 冷启动期内容厚度不够 | 上线前储备 40 篇，建立 KOL/编辑合作流程 |
| **活动信息采集成本高** | 编辑人工收集效率低 | 建立舞室/赛事方主动提交流程，提供合作权益 |
| **代发被认定为 UGC** | 小程序审核驳回 | 强调预约/报名类目；用户提交不公开展示；备微信群方案 |
| **代发运营过重** | 审核积压、成局率低 | 冷启动单城；SLA 24h；成局率<15% 则收缩 |
| **留存难** | 无真社交 | 活动提醒 + 代发撮合回访 + 内容深度 |
| **竞品模仿** | PGC 内容和活动信息容易被抄 | 靠内容积累+活动关系网+用户习惯建立壁垒，不靠功能壁垒 |

## 十、总结

舞岛非社区版 v1.3 是**资质约束下的验证产品**——用「PGC 内容 + 活动平台 + **代发练舞撮合**」在个人主体下尽可能接近原 MMVP 的搭子价值。

**v1.3 的核心命题**是验证三件事：
1. **街舞垂类专业内容有没有人看**
2. **活动信息 + 提醒能不能让人回来**
3. **找搭子需求是否真实**（代发撮合成局率）

三项中 **代发成局率** 是是否注册公司的关键决策依据。达标 → 注册有限公司 + ICP → v2 真 UGC 搭子。

**v1.3 不是终态**——代发是搭子的临时形态，不是长期产品形态。
