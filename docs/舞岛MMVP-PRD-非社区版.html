01资质约束与设计原则

1.1 硬约束（个人主体小程序）

能力状态原因
PGC 资讯发布✅ 可做资讯类目，企业/个人主体均可
工具类功能✅ 可做工具类目
用户发布内容（UGC）❌ 禁止需社交类目，个人主体不可申请
找搭子/搭子帖❌ 禁止属于用户发布内容
评论/点赞/收藏❌ 禁止互动类功能需社交类目
支付/交易/拼团❌ 禁止无微信支付商户号
商城/电商❌ 禁止需电商类目

1.2 设计原则

  • 纯单向输出：所有内容由平台/合作方生产，用户只消费不产生
  • 工具做留存：节拍器是日活引擎，赛事日历是周活引擎，舞室地图是月活引擎
  • 无登录可用：不强制登录，工具和内容都可直接使用；登录仅用于跨设备同步浏览历史
  • 商业化全部押后：v1 不碰钱，先做流量和工具使用习惯，资质解决后再补齐交易
  • 为升级留架构：内容对象模型预留评论/点赞字段（v1 不做 UI），未来升级企业主体后可快速补齐社交能力

04详细功能规格

4.1 账号体系（可选登录）

作为用户，我希望不登录就能看内容和用工具，以便零门槛体验
作为用户，我希望登录后能同步浏览历史，以便换设备后继续看
  • 未登录状态：全部功能可用（内容浏览、工具使用）
  • 登录方式：wx.login（静默登录，不弹授权框），不强制获取用户信息
  • 登录仅用于同步浏览历史到云端；不登录则浏览历史存本地
  • 不做用户主页、不做昵称头像展示（无社交场景，不需要身份）
  • 边界：微信授权被拒时不阻塞任何功能

4.2 首页内容流（tab1）

作为新手舞者，我希望刷到穿搭和康复内容，以便获得入门价值
作为圈内用户，我希望看到赛事和圈内资讯，以便有持续回访的理由
  • 帖子卡片展示：标题、封面图/视频首帧、摘要、分类色标、发布者名称、发布时间
  • 无点赞/收藏/评论数展示（无互动功能）
  • 帖子详情页：标题 + 正文 + 图片（多图全屏）+ 视频（内嵌）+ 发布者信息
  • 详情页无评论区、无互动按钮（底部只有"分享"）
  • 顶部双 tab：发现（全部内容）+ 城市名（按发布定位筛选，如"北京"）
  • 内容分类：穿搭 / 康复 / 文化 / 赛事 / 新鲜事 / 其他
  • 前置内容由运营后台发布，上线前储备 ≥40 篇（6 类 × 每类 ≥6 篇）
  • 信息流排序：时间倒序 + 置顶运营位，不做推荐算法
  • 视频支持外链上传（微信视频号链接或云存储）

4.3 内容详情页（编辑型长内容格式）

作为用户，我希望专注阅读内容，不被社交元素干扰
作为编辑/作者，我希望发布像知乎/公众号一样的编辑型长文，支持标题、引言、块引用、章节、图片混排

三种核心元素的定义和视觉规范

元素 1：标题（Title）

属性规范
语义文章主标题，概括全文核心
字号22px / 700
字色#1A1A1A（Ink）
行高1.3
副标题（可选）13px / 400 / #8A8A8E / 下 14px

元素 2：引言 / Call-out 提示块

属性规范
语义作者对读者的导读/提示/摘要，是作者自己的话（区别于块引用的"引用他人"）
使用场景① 文章开头的导读摘要 ② 文中重要提示/总结 ③ 推荐书单/装备清单的引出
背景#EEEDFE（浅紫底）
左边框4px solid #534AB7（主色）
圆角0 8px 8px 0（左直角右圆角）
内边距16px 18px
可选图标右上角 info icon，#534AB7，opacity 0.4
标题（可选）12px / 700 / #3C3489 / 大写 / letter-spacing 0.5px，如"导读""提示""推荐"
正文14px / 1.75 行高 / #3D3D3D
内嵌粗体b 标签用 #1A1A1A（比正文更深）
Call-out 视觉示意：左侧紫色色条 + 浅紫底 + 可选"导读"标题 + 段落正文。视觉权重高，吸引注意。

元素 3：块引用 / Blockquote

属性规范
语义引用他人内容（书籍原文、名人语录、其他文章片段），不是作者自己的话
使用场景① 引用书中原文 ② 引用舞者/老师的话 ③ 引用其他媒体内容
左边框3px solid #D1D5DB（灰色，克制不抢眼）
背景transparent（无背景色）
内边距4px 0 4px 16px（仅左侧缩进）
字号14.5px
字色#4A4A5A（比正文略浅）
字体italic（斜体，区分于作者正文）
来源标注 cite12px / #B0B0B4 / 非斜体 / 上边框 0.5px #E5E7EB / 前缀 "— "
Blockquote 视觉示意：左侧灰色竖线 + 无底色 + 斜体 + 来源标注。视觉权重低，克制不抢眼。

Call-out vs Blockquote 的区别

维度Call-out（引言）Blockquote（块引用）
语义作者自己的话引用他人的话
视觉紫色系（浅紫底 + 紫色左条）灰色系（透明底 + 灰色左线）
字体常规斜体
来源无 cite有 cite（来源标注）
用途导读/提示/摘要引文/语录/书中原文
视觉权重高（吸引注意）低（克制不抢眼）

其他验收标准

  • 无评论区、无互动按钮（无点赞/收藏/评论）
  • 底部分享栏：分享到微信会话/朋友圈
  • 关联内容推荐：详情页底部 3 条（按分类匹配）
  • 顶部阅读时长提示：如"阅读 12 分钟"，从字数自动计算
  • 边界：内容含外链视频时，视频在详情页内嵌播放
  • 后台编辑器：工具栏提供"插入 Call-out"和"插入 Blockquote"两个独立按钮，编辑可选择"引言"或"引用"类型

4.4 活动平台（tab2 核心）

作为舞者，我想看近期有哪些街舞赛事，以便决定参加哪个
作为进阶舞者，我想看大师课和 Workshop 信息
作为初学者，我想知道附近每周的 Jam / Cypher Night
  • 活动分类筛选 chips：全部 / 找搭子 / 赛事 / 大师课
  • 活动列表卡片：顶部彩色封面区（赛事=紫、大师课=橙红、Jam=绿）+ 类型徽标 + 日期标签 + 大字标题 + 描述 + 元信息（地点/时间）+ 关注数 + "查看详情 →"
  • 活动详情页：彩色 hero 区（类型徽标+大标题）+ 活动信息卡（时间/地点/舞种/主办 4 行 icon+文字）+ 活动介绍 + 日程安排（时间轴列表）+ 注意事项 + 底栏"关注活动（赛事提醒）"
  • 关注功能：调用 wx.requestSubscribeMessage，赛前 3 天/1 天推送订阅消息提醒
  • 找搭子入口：活动列表顶部固定紫色 banner「找练舞搭子 · 提交需求，审核后官方代发 →」，点击进入搭子需求表单（§6.4）
  • 活动数据全部由运营 PGC 维护，用户不创建活动
  • 边界：活动报名跳转外部 H5/公众号，不在站内完成

4.5 个人中心（tab3）

作为用户，我希望看到我浏览过的内容，以便回看
  • 浏览历史：最近浏览的内容列表（本地存储，登录后同步云端），按时间倒序，最多 100 条
  • 清空历史：一键清空浏览历史
  • 设置：通知开关（赛事提醒）、关于舞岛、用户协议、隐私政策
  • 不做：发帖、收藏、点赞列表（无此功能）
  • 不做：消息中心（无社交互动，无消息来源）
  • 不做：草稿箱（无发帖功能）
  • 登录入口（可选）："登录同步浏览历史"，不强制

4.7 个人中心·关注的活动（P1）

作为用户，我希望看到我关注过的活动，以便回看
  • "我的"列表新增"关注的活动"cell，带关注数 badge
  • 点击进入活动关注列表：按关注时间倒序
  • 取消关注：活动卡点击取消，回到活动列表
  • 边界：未登录状态显示"登录后可跨设备同步关注"

4.8 搜索（P1）

作为用户，我希望搜"Breaking 护腕"快速找到相关内容
  • 入口：首页顶栏 toptabs 左侧搜索 icon
  • 搜索对象：仅 PGC 内容（无用户内容可搜）
  • 搜索维度：关键词匹配（标题 + 正文）+ 分类标签
  • 初始态：搜索框 + 热门搜索（运营配置 6-8 个词）
  • 结果态：按时间倒序，复用内容流卡片样式
  • 空结果态：引导"试试 [热门词]"

4.9 打卡挑战（通用能力）

定位：把"21 天 Breaking 基础训练"这类官方打卡活动抽象成通用能力——官方在后台发布任意主题的打卡挑战，用户加入后每日打卡，完成后获得成就海报并分享。不依赖 UGC（用户只点按钮不产生公开内容）、不依赖支付（奖励是电子海报）。
作为新手舞者，我看到"21 天 Breaking 基础训练"挑战，加入后每天跟着任务练基本功
作为用户，我希望每天打开小程序时能看到"今日打卡"入口，点一下就完成打卡
作为用户，我完成 21 天后能获得一张好看的成就海报，分享到朋友圈
作为运营，我希望能在后台发布不同主题的打卡活动（Breaking/Hip-hop/Locking/康复...）

功能流程

官方发布挑战（PGC 后台）
    ↓
用户浏览挑战列表（活动 tab 内"挑战"入口）
    ↓
查看挑战详情（封面 + 描述 + 每日任务 + 参与人数 + "加入挑战"按钮）
    ↓
点击"加入挑战"→ 弹出一次性订阅消息授权（"每日打卡提醒"模板）
    ↓
每日打卡：
  入口 1：首页顶部 banner"今日打卡 Day 14/21 →"
  入口 2：我的 → "我加入的挑战" → 今日打卡按钮
  动作：点击"今日打卡"按钮 → 记录打卡 + 进度+1 + 连续天数+1
  反馈：打卡成功动画 + 今日任务卡片翻转展示
    ↓
断卡处理：断卡 1 天连续天数归零（已打卡天数不归零）；每月 1 次补签卡
    ↓
完成挑战（已打卡天数 = 总天数）：
  生成成就海报（紫色主调 + 标题 + 用户名 + 天数 + 日期 + 二维码）
  海报可保存到相册 + 分享到微信会话/朋友圈

验收标准

  • 挑战列表：活动 tab 顶部"挑战"入口，展示招募中 + 进行中的挑战卡片
  • 挑战详情：封面 + Call-out 描述 + 每日任务预览（前 3 天）+ 参与人数 + "加入挑战"按钮
  • 加入挑战：点击后调用 wx.requestSubscribeMessage 订阅"每日打卡提醒"模板
  • 每日打卡入口：首页顶部 banner（仅加入后显示）+ 我的页"我加入的挑战"列表
  • 打卡动作：点击"今日打卡"按钮 → 打卡成功动画 + 进度条更新 + 连续天数更新
  • 进度可视化：环形进度条（已打卡/总天数）+ 连续天数火焰图标
  • 断卡：断卡 1 天连续天数归零；每月 1 次补签卡
  • 完成挑战：自动生成成就海报（Canvas 渲染 → 临时图片）
  • 成就海报：紫色渐变背景 + 挑战标题 + 用户名 + "21/21 天完成" + 日期范围 + 舞岛 logo + 小程序码
  • 分享：海报保存到相册 + 分享到微信会话 + 分享到朋友圈（图片分享）
  • 边界：同一用户可加入多个挑战；已结束后不可再加入；打卡需在当日 0:00-23:59 内完成

4.10 通知能力（通盘设计）

约束：微信小程序一次性订阅消息——每次用户授权只能推送一条消息，需用户主动点击触发，模板需在微信公众平台后台配置审核。策略：在用户有明确利益动机的时刻请求订阅，并在每次推送后引导重新订阅。

验收标准

  • 活动关注：关注时调用 wx.requestSubscribeMessage，订阅 2 次（赛前 3 天 + 1 天）
  • 打卡提醒：加入挑战时调用 wx.requestSubscribeMessage
  • 打卡重订阅：每日首次打开时，如已加入挑战且今日未打卡且未订阅 → 首页顶部轻提示"订阅今日打卡提醒 →"
  • 本周精选：设置页开关，开启时调用 wx.requestSubscribeMessage
  • 活动结果：活动结束后自动推送，复用活动关注时的订阅额度
  • 推送内容：每条含标题 + 摘要 + 跳转路径（点击直达详情页）
  • 重订阅引导：每条推送后记录"已消耗订阅"，下次打开相关页面时引导重新订阅
  • 用户拒绝订阅：不阻塞功能，只是不推送提醒
  • 设置页：通知开关——活动提醒 / 打卡提醒 / 每周精选，可单独开关
  • 边界：一次性订阅额度用完后不报错，静默不推送
