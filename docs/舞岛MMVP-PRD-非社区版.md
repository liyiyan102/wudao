## 1. 产品概述

**定位**：年轻街舞人的内容资讯 + 官方活动平台 + **代发练舞撮合**。

个人主体不可做 UGC 社区（用户公开发帖/评论/搭子帖）。全部**公开展示内容**由运营经 PGC 后台发布；用户侧为内容消费 + 活动参与 + **私密需求提交**（审核后代发为官方练舞局）。

**合规定位（提审口径）**：

| 对外说法 | 实际机制 |
|---|---|
| 「官方活动发布与预约报名平台」 | 赛事/Jam/大师课 = PGC 活动 |
| 「练舞需求登记，平台审核后代发」 | 用户填表 → 不公开展示 → 运营编辑发布 |
| 「活动报名，联系方式仅发起人可见」 | 应征 = 结构化表单，非公开 UGC |

**类目建议**：生活服务 > 工具 > **预约/报名**（主）+ 资讯展示（辅）。**不选**社交-社区/论坛。

### 1.1 三句话验证假设

| # | 假设 | 验证方式 | 4 周目标 |
|---|---|---|---|
| 1 | 垂类 PGC 内容能否留人 | 阅读深度、次周留存 | 次周留存 ≥20%；人均内容 PV ≥3 |
| 2 | 活动信息能否让人回来 | 关注率、提醒打开率 | 活动关注转化 ≥15% |
| 3 | **找搭子需求是否真实**（代发撮合） | 需求提交量、代发率、应征率、成局率 | 见 §9 |

### 1.2 资质边界

| 能力 | 个人主体 | 公司 + ICP 备案 |
|---|---|---|
| PGC 内容/活动 | ✅ | ✅ |
| 代发撮合（本方案） | ✅ 灰色可试 | ✅ |
| 用户自发搭子帖、评论、点赞 | ❌ | ✅ |
| 支付/商城 | ❌ | ✅（另需商户号） |

> **个体工商户不能替代公司解锁真 UGC 搭子**；v2 社交能力前置条件 = 注册**有限公司** + ICP 备案 + 社交类目 + 内容安全体系。

## 6. 代发撮合（方案 B 核心）

### 6.1 设计原则

```
用户填需求（私密，不公开展示）
        ↓
运营审核 + 编辑成 PGC 练舞局
        ↓
公开发布在活动列表
        ↓
他人「我想加入」应征（联系方式仅发起人可见）
        ↓
发起人线下联系成局 → 运营标记「已结束」
```

**与真 UGC 搭子的差异**：

| 维度 | 真 UGC（v2） | 代发撮合（v1.3） |
|---|---|---|
| 谁发布 | 用户一键发布 | 用户提需求，运营代发 |
| 公开内容归属 | 用户账号 | 舞岛官方账号 |
| 审核 | 先审后发 / 内容安全 API | 人工审核后再发布 |
| 合规类目 | 社交-社区/论坛 | 工具-预约/报名 |

### 6.2 数据模型

**BuddyRequest（搭子需求，用户提交，不公开展示）**

| 字段 | 说明 |
|---|---|
| id | UUID |
| uid | 提交者标识（wx.login openid 或端侧匿名 UID） |
| subType | 练舞 / 拼团 / 找队友 / 其他 |
| title | 必填，≤30 字 |
| description | 选填，≤500 字 |
| danceStyle | 舞种，选填 |
| city | 必填 |
| location | 地点文本或 chooseLocation |
| datetime | 必填，日期+时间 |
| headcount | 期望人数，选填，默认「不限」 |
| contactWechat | 发起人微信号，必填 |
| contactPhone | 手机号，选填 |
| refImages | 参考图 ≤3，选填，**仅审核可见，发布时不展示原图** |
| status | pending / approved / rejected / published / closed |
| rejectReason | 驳回原因 |
| linkedActivityId | 审核通过后关联的活动 ID |
| createdAt / updatedAt | 时间戳 |

**Application（应征，私密）**

| 字段 | 说明 |
|---|---|
| id | UUID |
| activityId | 关联练舞局 |
| requestId | 关联源需求 |
| applicantUid | 应征者 |
| message | 一句话说明，选填，≤100 字 |
| contactWechat | 必填 |
| contactPhone | 选填 |
| createdAt | 时间戳 |

**Activity 扩展（练舞局类型）**

| 字段 | 说明 |
|---|---|
| type | `buddy`（练舞局） |
| buddySubType | 练舞/拼团/比赛/其他 |
| sourceRequestId | 源需求 ID |
| initiatorUid | 发起人（查看应征用） |
| headcount | 人数缺口 |
| applicationCount | 应征数（公开展示） |
| status | recruiting / full / ended |

### 6.3 用户故事

- 作为练舞用户，我想填表说明时间地点和舞种，让平台帮我发练舞局，而不自己公开发帖
- 作为应征者，我想点「我想加入」留联系方式，让发起人联系我，且别人看不到我的联系方式
- 作为发起人，我想在「我的搭子需求」里看到谁应征了，方便筛选联系
- 作为运营，我想审核需求、编辑文案、一键发布为练舞局，并拒绝违规/广告内容

### 6.4 提交搭子需求（buddy-request）

**入口**：

1. 活动 Tab 顶 banner「找练舞搭子」
2. 活动列表练舞局 chip 空态：「暂无练舞局，提交你的需求 →」
3. 我的 → 「提交搭子需求」

**表单结构**（视觉主角 = 时间地点 key-block，参考原 MMVP 搭子发布页）：

| 区块 | 字段 | 必填 |
|---|---|---|
| 类型 | 练舞 / 拼团 / 找队友 / 其他 | ✅ |
| 标题 | ≤30 字 | ✅ |
| 时间地点 | 日期+时间 + 城市 + 地点（chooseLocation） | ✅ |
| 描述 | ≤500 字 | — |
| 舞种 | 下拉或文本 | — |
| 人数 | 数字或「不限」 | — |
| 联系方式 | 微信号 + 可选手机号 | ✅ |
| 参考图 | ≤3 张，仅审核用 | — |

**提交前勾选**：「我已阅读并同意《搭子代发须知》——需求由舞岛审核后发布，请勿填写违规内容」

**提交后**：跳转 buddy-request-success，展示「预计 24 小时内审核，通过后在活动列表展示」+ 「查看我的需求」。

**登录**：提交时触发 wx.login（需绑定 uid，否则无法查看应征）。

**边界**：

- 同一 uid 同时 pending 的需求 ≤3 条
- 文本过短/含广告引流关键词 → 客户端弱提示，服务端必审
- 参考图走 upload + 服务端粗筛（建议接 msgSecCheck）

### 6.5 审核与代发（PGC 后台，见后台 PRD §5.5）

```
pending 需求进入后台队列
    ↓
运营审：通过 / 驳回（填原因）
    ↓
通过 → 预填活动编辑器（标题/时间/地点/描述/类型）
    ↓
运营润色 → 发布为 type=buddy 活动
    ↓
需求 status=published，linkedActivityId 写入
    ↓
（可选）订阅消息通知发起人「你的练舞局已发布」
```

**发布规则**：

- 发布账号 = 舞岛官方号（非用户头像昵称直出）
- 正文不含发起人联系方式
- 描述中不出现「加微信 xxx」等引流（联系方式仅应征通道给发起人）

### 6.6 应征流程（我想加入）

Given 用户在练舞局详情页点击「我想加入」  
When 填写一句话说明（选填）+ 微信号（必填）+ 手机号（选填）  
Then：

- 提交成功，按钮变为「已应征」置灰
- 发起人可在「我的搭子需求 → 该条 → 应征列表」查看
- **应征者之间互不可见**；公开页不展示任何联系方式
- applicationCount +1

**边界**：

- 同一用户对同一练舞局重复应征 → 提示「已应征过」
- 活动 status=ended → 按钮置灰「已结束」
- 发起人不能应征自己的局

### 6.7 发起人管理（my-buddy-requests / buddy-applications）

**我的搭子需求列表**：

| 状态 | 展示 | 操作 |
|---|---|---|
| pending | 审核中 | 查看详情；可撤回 |
| rejected | 已驳回 + 原因 | 修改重提（新 request） |
| published | 已发布 · 应征 N 人 | 查看应征列表；分享活动 |
| closed | 已结束 | 只读 |

**应征列表页（buddy-applications）**：

- 每条：应征时间 + 一句话 + 微信号（点击复制）+ 手机号
- 顶部提示：「请通过线下/微信自行联系，舞岛不参与交易与担保」

**结束练舞局**：

- 发起人可点「标记已结束」（或运营后台标记）
- 结束后停止接受应征

### 6.8 合规与风险控制

| 风险 | 应对 |
|---|---|
| 被认定为 UGC 社区 | 用户提交=私密表单；公开=PGC；提审材料强调预约/报名 |
| 审核不及时 | 冷启动承诺 24h 内；pending 超 48h 自动提醒运营 |
| 虚假/广告需求 | 人工审核 + 关键词过滤 + 驳回机制 |
| 线下安全 | 《搭子代发须知》免责声明；不推荐未成年人单独赴约 |
| 审核尺度变化 | 保留微信群作备用撮合通道，不 all in 小程序 |

### 7.3 题目与计分规则

**10 道场景题**，每题 6–8 个选项（选项数按人格覆盖需要给，不强行凑齐 4 个）。刻意用场景题而非直问（「你喜欢编舞吗」会让人按身份作答）。

每个选项携带：`weights`（人格分）/ `music`（仅 Q1）/ `body` / `scenes` / `roles` / `echo`（写入结果解读）。

**总分算法**：

1. 人格分：10 题 `weights` 累加。主人格 = 第 1 名；副人格 = 第 2 名。
2. 同分：按对象 key 字符串排序后取先者（无专门平局处理）。
3. 全空兜底：主 `resonance`，副 `groove`。
4. 音乐 DNA：只累计 **Q1** 的 `music`，取 Top（实际即该选项的 1–2 个标签）。
5. 身体语言 / 常在战场 / 角色：各题对应标签每命中 +1，分别取 Top2 / Top3 / Top2。

**题目定位**：题目携带 `kind` 标记（`music` / `fear` / `keep`），结果文案按 `kind` 取答案而非按下标，增删题目不会让文案错位。

### 7.4 结果页完整文案结构

结果页不是套死一段人格简介，而是 **固定块 + 作答拼接块**：

| 区块 | 来源 | 是否随作答变化 |
|---|---|---|
| 票根编号 / 中英文名 / 核心特质 | 主人格表 | 否（随主人格） |
| headline 金句 | 主人格 `headline` | 否 |
| 解读第 1 段 | 主人格 `voice` | 否 |
| 解读第 2 段 | **Q1 / Q2 / Q3 命中选项的 echo 连写** | 是 |
| 解读第 3 段 | **`kind=fear` echo + `kind=keep` echo** | 是 |
| 解读末段 | 副人格名 + Q1 音乐标签 + Top 战场 | 是 |
| 你的天赋 | 主人格 `superpower` | 否 |
| 你的暗面 | 主人格 `shadow` | 否 |
| 标签 chips | `核心 + Top2 战场 + Top1 身体 + 默认 traits`，去重取 4 | 部分 |
| 4 格 DNA | 音乐 / 身体 / 战场 / 副人格名 | 是 |
| 岛上推荐 | `按你选过的场景，更适合先去：{映射}。` + 主人格 `need` | 部分 |

> 「天赋 + 暗面」是分享率最高的两块：天赋给人转发的理由，暗面给人「被说中了」的刺痛感。两者都随主人格固定，保证同一人格的文案在传播中可被辨认。

**「怕什么 → 留什么」连接规则**（语义对齐才用「所以」，否则并列、不硬圆）：

| 怕（Q9） | 留（Q10） | 是否对齐 |
|---|---|---|
| A 「你没什么音乐性」 | A 一首能循环到天亮的歌 | 是 |
| B 「你跳得没味儿」 | D 一段终于被拍出来的作品 | 是 |
| C 「你就是不敢上」 | C 一个让你上场的机会 | 是 |
| D 「你接不住别人，也带不起气氛」 | B 一个有人接你的练舞圈 | 是 |
| E 「你老拖队伍后腿」 | E 一支永远不散的队 | 是 |
| F 「你是不是跳不动了」 | F 一副不会再疼的膝盖 | 是 |
| 其余组合 | — | 否 → 两句直接相连 |

对齐时输出：`{怕 echo}` + 「所以到最后，」+ `{留 echo}`（留句首自动改写为「你要留下的就是」）。

### 7.6 结果分享（海报）

- 结果页仅保留一个分享入口「★ 分享我的街舞人格」，点击打开**海报预览弹窗**。

## 13. 成功指标

### 13.1 内容与活动（不变）

| 指标 | 目标 |
|---|---|
| 次周留存 | ≥20% |
| 人均内容 PV | ≥3 |
| 阅读完成率 | ≥40% |
| 活动关注转化率 | ≥15% |

### 13.2 代发撮合（新增）

| 指标 | 目标 | 口径 |
|---|---|---|
| 需求提交量 | 上线 4 周累计 ≥30 条 | 有效 pending+published |
| 审核通过率 | ≥70% | approved / submitted |
| 代发时效 | 中位 ≤24h | submitted → published |
| 练舞局应征率 | ≥30% | 有 ≥1 应征的局 / 已发布局 |
| 应征完成率 | ≥60% | 点击「我想加入」→ 提交成功 |
| **成局率** | ≥25% | 运营/发起人确认「已结束且成局」/ 已发布局 |
| 发起复购 | ≥20% | 成局发起人 30 天内再次提交需求 |

### 13.3 验证结论（4 周后）

| 结果 | 决策 |
|---|---|
| 三项（内容留存 + 活动关注 + 代发成局率）达标 | 注册**公司** + ICP 备案，启动 v2 真搭子 |
| 内容/活动行、代发不行 | 代发运营过重或需求假 → 收缩为纯资讯，搭子放微信群 |
| 代发行、内容弱 | 加强 PGC，代发作差异化留存 |
